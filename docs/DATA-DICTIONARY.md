# 字段与计算定义

## 收货回执与来源契约

一张回执至少带 `id`（磅单号）、`version`（正整数）与 `source`（来源）。
`source` 可用 `地磅`/`scale`、`化验`/`lab`、`完整`/`full`；缺省时按携带字段
识别：重量与水杂都带为完整回执，只带重量为地磅，只带水杂为化验。

| 来源 | 可承担字段 | 说明 |
|---|---|---|
| 地磅补传 | `bin` `gross` `tare` `unit` `net_kg` | 重量；可由毛重、皮重、单位算净重，也可直接给净重 |
| 化验复验 | `moisture` `impurity`（可回带 `bin`） | 水杂；回带的仓号只用于核对，不参与取值 |
| 完整回执 | 以上全部 | 必须一次带齐全部字段 |

显式声明为地磅却带水杂、声明为化验却带重量，返回 `SOURCE` 并隔离该行。
`trip`（车次）可选；缺省时取磅单号；两者都没有时用 `vehicle`+`weigh_time`（车牌与
过磅时间）兜底，保证同一辆车不同时刻的两趟不会并成一车。车次是入仓的唯一身份。

## 字段级裁决

同一车次内，**每个字段**分别按“提供该字段的最高版本”取值，而不是整行取
最高版本。典型场景：地磅 v1 只带重量，化验复验 v2 只带水杂，合成后重量来自
v1、水杂来自 v2。复验只覆盖自己承担的字段，不改变重量与原磅单身份。

- 同版同字段出现不同值：该车次整组隔离（`CONFLICT`），绝不任选一个。
- 同版同值：保留最早登记的原回执，其余计 `DUPLICATE`。
- 旧版字段被更高版本覆盖：旧回执计 `DUPLICATE`，但保留在事实的原回执清单里。
- 合并后缺字段：该车次记 `待续跑`（`MISSING`），不落事实；补传到达后续跑。
- 水分超过 `max_moisture`：该车次整组拒收（`LIMIT`），不落事实、不入仓；若该车次
  此前已入仓，有效复验会把它撤回（仓批移除、状态改 `退收`）。

## 收货事实

每张事实保留：`trip`、原磅单号 `id`/`ticket_id`（最早一张地磅或完整回执的
磅单号）、各字段取值、`_receipts`（全部原回执的摘要、原行、版本、贡献字段）
与 `evidence`（每个字段的来源行、来源、版本、原值与取值回执摘要）。派生字段
另记公式与输入字段。仓批与结算只读这张事实。

`net_kg`、`clean_kg`、`dry_kg`、`standard_kg` 为 Decimal 内部值；JSON 以字符串
输出。

## 计算与结算

净粮=净重×(1-杂质/100)，干物质=净粮×(1-水分/100)，折标重=干物质/(1-标准水分/100)。
标准水分与收购上限由批次参数给出，本流程只读不改。单价CNY/kg，按未舍入折标重
计算总额，再以最大余额法分配分币，余数相同按id升序。全部金额和重量为Decimal。

## 行数与原子性

输入逻辑行数 = 采信回执行数 + 隔离回执行数；空行单列。一张事实可能由多张回执
合成，所以追溯按“采信回执”计行数，不只按事实张数。每条重复、冲突、超限、缺失
均保留原始行号与原因码。

回执先落台账，事实切换与批次记录在同一 SQLite 事务提交；切换失败整体回滚，
页面看不到半张事实，未完成车次保持 `待续跑`，恢复后与其他输入一起续跑。
同一车次重试只更新原入仓流水（以 `trip` 为主键），不会重复入仓。

时间仅用于运行清单，保存UTC偏移。空值、哨兵、零分别处理，空文件/仅表头/全空行
返回不同原因码。规则参数纳入批次哈希。
